01The mandate

Every client wanted its own GenAI copilot. Building ten would not scale.

Each client asked for its own assistant. Building ten separate copilots would have been slow, expensive and inconsistent, so we designed one platform whose conversational engine, reasoning and UI could be configured and re-skinned per client.

Leadership decision · reusable core versus client configuration

Standardise the behaviours. Configure the expression.

The design direction separated what should remain consistent—conversation states, confirmation, fallback, handoff and core components—from what could change for each client: visual identity, tone, enabled capabilities and connected data. A bespoke request was assessed against this boundary before becoming a new pattern, rather than automatically creating a parallel product.

03Designing for uncertainty

Models are non-deterministic. The interface has to earn trust.

LLMs don't always follow multi-step logic perfectly. These patterns became part of the design system, so every client copilot handled uncertainty the same way.

01

Reasoning made visible

Show which sources were used when it builds trust; hide the workings when they only add noise.

ⓘ Checked profile, fares and dates · 3 sources Here are the cheapest direct options for July.
02

Confidence & fallback

When required data is missing or confidence is low, the copilot asks one clear question instead of guessing.

I want to go kitesurfing this summer. Great idea. How long would you like to go for?
1 week 2 weeks
03

Human handoff

Sensitive or high-stakes moments route to a person, with the conversation history passed along.

My flight was cancelled and I'm stuck. I'm sorry. I'm connecting you to an agent now and sharing your booking so you don't repeat yourself.
04

Feedback & confirmation

Nothing is booked, paid or changed without an explicit yes. Actions are reversible where possible.

✕ No ✓ Yes

Guardrails & compliance

04Configuration

White-label by parameter, not by redesign.

Each client is a set of parameters on the same components: brand tokens, tone of voice, connected data sources, enabled agents and content rules. Switch clients to see one chat component take on each configuration.
