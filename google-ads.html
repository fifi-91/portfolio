The challenge

One audit. Several systems. Hours of manual maths.

App campaign audits were done by hand. Specialists jumped between several internal systems, calculated budget thresholds manually, counted creative assets ad group by ad group, and copied everything into spreadsheets and slides. Frontline support teams often couldn’t access the data at all. It was slow, error-prone and impossible to scale. [TBC: optional scale line]

What I found

I started by auditing the existing prototype.

An early version of the tool already existed. Before designing anything new, I ran a heuristic review of each step against UX best practices, then turned every finding into a recommendation. That review set the direction for the redesign.

Design decisions

Every screen answers one question: what’s broken, when, and why?

Search by campaign, not just by client.

Most tickets are about one campaign, so specialists can go straight there.

Reveal options only when they’re needed.

The date range appears after an account is chosen, so the first step is one simple search.

A calendar, not a bar chart.

A 14-day heatmap shows exactly when a campaign broke and separates today’s problems from old ones.

Explain the failure, not just flag it.

A failure-details sidebar shows the actual value, the required threshold and what to fix.

One tool for three teams.

A shared layout with role-relevant detail, instead of three separate tools.

The experience

From search to root cause in a few clicks.

The system

Built from a shared system so the design team ships one product.

Data-heavy tools fall apart when every screen invents its own patterns. We defined shared components for status, filters, tables and timelines, so every part of the tool feels the same and engineering builds each pattern once.
